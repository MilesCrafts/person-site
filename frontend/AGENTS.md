# LEKANG JOURNAL 前端协作规则

本文件只保存长期有效、可执行的前端协作规则，不记录临时任务、每日进度或当前完成度。

## 1. 适用范围与继承

- 本文件适用于 `D:\lekang\frontend` 目录及其全部子目录。
- 根目录 `D:\lekang\AGENTS.md` 中的全局规则继续有效；开始任务前必须同时阅读根规则、本文件、任务涉及的现有文件，以及 `docs/` 中相关架构、接口和状态文档。
- 出现冲突时，用户当前明确指令优先；其后遵循根目录全局规则与本文件中更具体的前端规则。
- 本文件只补充前端专用规则，不取代根目录规则。
- 前端任务不负责修改 `backend/`、`deploy/`、线上服务器或其他模块所有者负责的文件。
- 跨模块修改前必须报告涉及文件、接口影响、验证范围和文档更新范围，并获得用户授权及对应模块所有者协调。
- 修改前先只读检查相关文件和 Git 状态；若当前目录不是 Git 工作区，必须如实报告，不得假设分支或 Worktree 存在。

## 2. 产品与设计方向

- LEKANG JOURNAL 2.0 第一阶段是文章优先的现代个人内容网站，核心任务是让用户快速发现、筛选、搜索和阅读文章，不建设综合个人主页、Dashboard 或 SaaS 官网。
- 当前公开范围只包括文章首页、文章列表、文章详情、搜索和归档；个人介绍、近期状态、电影/足球/阅读/生活独立模块、影集扩展及沉浸式滚动开场均延期，已有 URL 和数据能力只做兼容保留。
- 信息层级和文章可读性优先于装饰，图片只服务于文章封面与内容表达，不为填满版面而增加图片或模块。
- 使用稳定网格、充分留白、轻边框、克制圆角和清晰字体层级；可以使用文章卡片，但不得堆成后台指标卡或用阴影代替层级。
- 不采用 Material Design、后台侧栏、统计图表、大面积渐变、发光效果、毛玻璃叠层、胶囊按钮泛滥或明显的 AI 模板式多彩界面。
- 固定设计基线如下；实现时优先复用 `src/assets/styles/_variables.scss` 中的现有变量：
  - Background：`#FFFFFF`
  - Subtle Background：`#F7F8FA`
  - Text：`#101828`
  - Secondary：`#667085`
  - Border：`#E4E7EC`
  - Accent：`#3157D5`
  - Accent Subtle：`#EEF2FF`
  - 标题与正文：Inter、Arial、Helvetica、PingFang SC、Microsoft YaHei 及合适的系统无衬线回退字体
- 除非用户明确要求再次调整，后续公开站修改必须遵循本文 2.0 文章优先视觉方向。

## 3. 技术栈约束

- 保持当前 Vue 3、Vite、TypeScript、Vue Router 和 SCSS 技术栈。
- Vue 组件使用 Composition API 和 `<script setup lang="ts">`。
- 不擅自迁移到 React、Next.js、Nuxt 或其他框架。
- 不引入大型 UI 组件库。
- 不引入 Pinia 等状态库，除非已经出现明确、持续的跨页面共享状态需求，并完成方案评估。
- 不增加依赖来解决可由现有技术简单、清晰完成的问题。
- 新依赖加入前必须说明用途、包体积或构建影响、维护成本和不引入该依赖的替代方案，并获得授权。
- 保持 TypeScript 严格模式；不得通过放宽编译选项掩盖类型问题。

## 4. 目录职责

当前前端工程已经位于 `frontend/`，实际存在 `src/views`、`src/components`、`src/router`、`src/data`、`src/assets` 和 `public`；`src/api` 与 `src/types` 尚未建立。各目录长期职责如下：

- `src/views/`：Vue Router 对应的路由页面。
- `src/components/`：可复用的界面组件。
- `src/router/`：路由配置、路由元信息与导航行为。
- `src/data/`：接入真实 API 前的过渡期本地数据；不得在生产环境把它当作接口失败的隐式兜底。
- `src/api/`：后端 API 客户端、请求封装和传输层适配；首次接入 API 时按需创建。
- `src/types/`：跨页面、跨组件或跨 API 模块共享的 TypeScript 类型；出现相应需求时按需创建。
- `src/assets/`：由 Vite 处理的图片、字体和全局样式等构建期资源。
- `public/`：无需 Vite 转换、需要以稳定公开路径提供的静态资源和托管辅助文件。
- API 请求不得散落在 Vue 组件中。
- 不把大型页面及其全部业务、展示与数据逻辑长期堆在单个组件内，也不进行没有维护收益的过度组件化。
- 页面专用逻辑可以保留在页面组件或其附近；公共逻辑稳定复用两次以上，再考虑提取为组件、组合函数或工具。
- 不为满足规划中的目录外观而创建空目录、移动代码或重写 import。

## 5. 路由规则

- 保留 Vue Router 的 History 模式，当前使用 `createWebHistory(import.meta.env.BASE_URL)`。
- 不随意修改已有公开路径。当前路由包括：
  - `/`
  - `/journal`
  - `/article/:id`
  - `/about`
  - `/archive`
  - `/search`
- 现有未知路由策略为重定向到 `/journal`；修改为独立 404 页面或其他策略前必须评估公开链接、用户体验与部署影响。
- 文章公开标识和 slug 必须保持稳定；当前详情参数名为 `id`，其中承载稳定文章标识，例如 `messi-world-cup`。
- 新增或修改路由前必须检查 Nginx 或静态托管是否保留 `index.html` 回退；当前 `public/_redirects` 也承担 SPA 回退职责。
- 页面切换后保持正确滚动位置，同时尊重减少动态效果的用户偏好；不得让平滑滚动妨碍可访问性。
- 未知路由必须有明确的回退或 404 策略，不得产生空白页面。
- 不通过创建真实 HTML 文件代替 Vue 路由页面。

## 6. API 接入规则

- 正式环境 API 基础路径使用同域相对地址 `/api/v1`，不得写死服务器 IP、端口或生产域名。
- API 访问统一放在 `src/api/`；Vue 组件不直接调用散落的 `fetch`，也不自行拼接后端 URL。
- 请求参数、响应 DTO 和错误结构必须有明确的 TypeScript 类型。
- 组件不得直接依赖 JPA Entity、数据库表结构或仅对后端内部有意义的字段。
- 列表接口必须支持契约定义的分页结构、稳定排序及分页元数据。
- 异步页面必须明确处理 loading、empty、error 和 success 状态；需要重试时提供可理解的重试入口。
- 接口错误不能静默回退到假数据，也不能把旧数据误呈现为最新请求成功。
- 本地 Mock 数据可作为显式的开发过渡方案；生产构建不得把 Mock 当作真实数据或失败兜底。
- API 字段或语义变化应先更新版本化 OpenAPI 或接口契约，再修改 API 类型和组件。
- 对可取消的请求使用 `AbortController` 或等价机制，避免组件卸载、路由切换或新请求开始后继续更新过期状态。
- 错误展示应依据统一错误契约，不向用户暴露堆栈、SQL、内部配置或敏感信息。

## 7. 组件和 TypeScript 规则

- 优先使用明确的 props、emits、返回值和领域类型。
- 禁止无必要使用 `any`；确实无法预知的外部输入先使用 `unknown` 并完成类型收窄。
- 不直接修改 props；需要本地编辑状态时显式建立副本并定义同步边界。
- 派生数据优先使用 `computed`，副作用才使用 `watch` 或 `watchEffect`。
- DOM 事件、定时器、观察器和其他外部订阅必须在组件卸载时清理。
- 列表渲染必须使用稳定、具业务意义的 key，不得在可变列表中用数组下标代替稳定标识。
- 避免在模板中放置复杂业务逻辑；复杂条件与格式化应进入有类型的计算属性或函数。
- 用户可见文字保持自然、克制，使用“最新文章”“阅读全文”“归档”等直接表达，减少 `FEATURE`、期号和编辑部式文案。
- Vue 组件文件与组件名使用 PascalCase；组合函数使用 `useXxx` 命名。
- 保持组件公开接口小而清晰，不通过全局变量或隐式 DOM 约定传递状态。

## 8. 样式规则

- 优先复用现有 SCSS 变量和排版系统，不在页面中重复散落颜色与字体常量。
- 页面最大内容宽度保持约 1200px；当前 `.container` 的 1280px 上限是既有视觉基线，未经整体页面验证不擅自改动。
- 文章正文宽度保持约 720px，以可读性为优先。
- 主要模块间距通常保持 64px 到 96px，并根据响应式布局有节制地缩减。
- 卡片圆角原则上使用 12px 到 16px；允许浅背景或细边框卡片，不使用厚重阴影、发光或过大圆角。
- 图片比例按内容场景优先使用 16:9 或 4:3；人物海报等有明确构图需求的素材可保留合适比例。
- 标题采用现代无衬线字体，以字重、字号和间距建立清晰层级，不使用巨型杂志标题。
- 动画只使用必要的淡入、颜色、下划线和轻微 scale 等克制效果。
- 不加入 3D、粒子、复杂滚动动画或视频背景，除非用户明确要求并已评估性能、可访问性和降级方案。
- V2-4 允许在首页加入一个基于 [GSAP](https://gsap.com/) 的“文章卡片叠 / Article Deck”特色组件：使用最近 4～5 篇真实文章，通过点击、拖动或触控滑动切换前景卡片；不得自动播放、劫持页面滚动、加入粒子/发光/渐变或扩展成全站动画框架。
- Article Deck 必须可用键盘操作并提供普通文章列表语义；`prefers-reduced-motion` 下停用位移动画，GSAP 加载或运行失败时降级为静态卡片列表。实现前仍须说明新增依赖、生产包体积和懒加载边界，不为该组件引入无关插件。
- 样式修改必须检查选择器作用域和其他页面回归，避免全局样式意外污染。
- 禁止使用 `!important` 解决普通优先级问题；确有第三方样式隔离等明确原因时必须留下简短说明。

## 9. 响应式规则

- 受影响页面至少验证桌面 1280px、平板 768px 和手机 375px 三个视口。
- 响应式设计不能只是等比例缩小桌面布局，应按阅读顺序、内容优先级和触控方式重新组织。
- 手机端保持可阅读字号、合理行长和足够触控区域。
- 导航不得溢出、重叠或产生不可访问的入口。
- 图片、表格和长文本不得造成页面横向滚动。
- 标题不得遮挡关键图片内容；使用覆盖排版时要检查不同标题长度和图片焦点。
- 手机端可以适度减少装饰，但不能丢失主要内容和导航入口。
- 使用 `dvh`、`safe-area-inset-*` 等特性时提供合理的旧浏览器降级值。
- 不得仅凭代码或单个截图声称响应式验证完成。

## 10. 图片和静态资源

- 优先使用项目内可控资源或经确认可靠的对象存储。
- 禁止在浏览器资源 URL 中引用 `C:\`、`D:\` 等客户端无法访问的绝对本地路径。
- 内容图片必须提供有意义的 `alt`；纯装饰图片使用空 `alt`，不得填入无意义文件名。
- 文章卡片等非首屏图片应考虑 `loading="lazy"`、合适尺寸和布局占位。
- Hero 首图或最大内容绘制候选图应避免懒加载，并谨慎决定是否预加载。
- 新增大图前检查像素尺寸、显示尺寸、压缩质量和文件体积。
- 派生资源优先使用 WebP 或 AVIF，同时按实际浏览器支持和回退需求选择格式。
- 不擅自删除、替换、裁切或重新压缩用户原始图片。
- 图片调整应保持自然、清晰和统一比例，不叠加高饱和渐变、发光或模板化滤镜。
- Vite 生成的带内容哈希资源可以长期缓存；未带哈希且 URL 稳定的资源必须采用适合更新策略的缓存时间。

## 11. 可访问性

- 使用与内容结构匹配的语义化 HTML，保持合理标题层级和地标区域。
- 所有交互必须可通过键盘操作，不使用只能依赖 hover 或指针手势的关键功能。
- 只有图标或符号的按钮必须有准确的 `aria-label`。
- 保证正文、次要文字、链接、边框和交互状态与背景具有足够对比度。
- 不只使用颜色表达选择、成功、警告或错误状态。
- 动画和自动滚动必须尊重 `prefers-reduced-motion`。
- 表单字段必须有关联的可见 `label`，错误信息应能被辅助技术识别并关联到字段。
- 焦点样式不能无替代地删除；自定义焦点样式必须清晰可见。
- 图片轮播、弹层、菜单等复合交互需要正确管理焦点、键盘行为和状态标注。

## 12. 性能要求

- 避免一次加载所有大型图片、视频或其他媒体。
- 路由页面继续使用合理的动态导入；首屏必需页面和资源是否同步加载应以实际体验和构建结果判断。
- 不把大型数据集、文章全文或不属于首屏的内容全部塞进首页包。
- 避免不必要的 `watch`、深度监听和频繁 DOM 测量。
- 高频滚动与 resize 事件使用 passive listener、`requestAnimationFrame` 或合理节流，并在卸载时清理。
- 动画优先使用 `transform` 和 `opacity`，避免持续触发布局和重绘。
- 不为微小视觉效果引入大型依赖。
- 构建完成后关注 JS、CSS 和图片体积变化；出现明显增长时说明来源、影响与优化选择。

## 13. SEO 和页面信息

- 每个公开页面必须有合理、与内容匹配的 `title` 和 `description`。
- 文章页使用文章标题作为页面标题，并在路由切换时正确更新页面元信息。
- 内容图片必须有准确的 `alt`。
- 公开 URL 和已发布 slug 保持稳定；变更前必须有兼容与重定向方案。
- 增加动态文章数据时同步规划 sitemap、RSS、canonical、Open Graph 和其他社交分享信息。
- 当前为客户端渲染 SPA；未采用 SSR、预渲染或经过搜索引擎实测前，不宣称已经解决全部 SEO 问题。

## 14. 修改边界

禁止以下行为：

- 未经授权修改后端代码。
- 未经授权修改 Nginx、宝塔、域名、DNS、SSL 或线上服务器。
- 未经授权删除、移动或替换已有页面、路由、图片、文章和数据。
- 为实现局部功能重写整个前端或扩大重构范围。
- 擅自更换技术栈、构建工具或 UI 框架。
- 修改任务范围之外的页面和样式。
- 使用 `git reset --hard`、强制推送或其他破坏性 Git 命令。
- 覆盖用户未提交修改或清理来源不明的文件。
- 未执行适当验证就宣称功能完成。
- 未经明确要求提交、推送、合并、变基或部署。

## 15. 验证要求

- 每次验证前必须先读取当时的 `package.json`、锁文件和相关配置，以实际存在的脚本与工具为准，不得编造命令。
- 当前 `package-lock.json` 存在，应检查其与 `package.json` 和依赖安装方式的一致性；需要重新安装时优先选择可复现的 `npm ci`，但不得为纯文档任务无意义地改动依赖或生成物。
- 当前 `npm run build` 执行 `vue-tsc -b && vite build`，同时覆盖 TypeScript 检查与生产构建；脚本变化后以实际配置为准。
- 前端代码或页面任务通常至少验证：
  - 依赖清单和锁文件一致性
  - TypeScript 检查
  - `npm run build`
  - 受影响的关键路由、直达与刷新
  - 浏览器控制台错误
  - 1280px、768px、375px 响应式布局
  - loading、empty、error 和 success 状态
- 重点路由包括：
  - `/`
  - `/journal`
  - `/article/messi-world-cup`
  - `/about`
  - `/archive`
  - `/search`
- 验证应与变更风险成比例；仅修改 Markdown 协作规则时，不要求运行会写入 `dist/` 的前端构建，但必须检查文档内容、作用域和实际配置是否一致。
- 如果验证无法运行，交付时必须逐项说明未运行内容、原因和可能风险。
- 不能把“代码看起来正确”或静态阅读表述成“验证通过”。

## 16. 完成任务后的输出

每次前端任务完成后报告：

- 完成内容
- 修改文件
- 页面或交互变化
- 实际执行的验证及结果
- 未验证事项及原因
- 已知风险
- 是否需要后端或部署模块配合

只有任务明确要求时才更新 `D:\lekang\docs\frontend-status.md`。不得擅自更新由总控维护的 `D:\lekang\docs\status.md`，也不得把计划写成已完成。
